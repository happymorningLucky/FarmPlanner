🚜 สรุป: แอป "Farm Planner (สวนสุขจันท์)" คืออะไร?
แอปพลิเคชันจัดการฟาร์มและจดบันทึกมาตรฐาน GAP (Good Agricultural Practices) สำหรับสวนผลไม้/การเกษตร ออกแบบมาเพื่อให้ใช้งานง่ายบนมือถือและคอมพิวเตอร์ โดยมีฟีเจอร์หลักคือ:

ระบบคุมสต๊อก (Inventory Management):
จัดการปุ๋ยและยา/สารเคมี
รองรับระบบ "หน่วยซื้อ (เช่น กระสอบ/ขวด)" และ "หน่วยใช้งานจริง (เช่น กิโลกรัม/ซีซี)" พร้อมการแปลงหน่วย (Conversion Rate) อัตโนมัติ
มีระบบลบทีละหลายรายการ (Batch Delete)
ระบบปฏิทินแผนงาน (GAP Calendar Planner):
สร้างงานรายวัน เช่น ใส่ปุ๋ย, พ่นยา, ตัดหญ้า พร้อมระบุชื่อ "แปลง"
ผูกรายการพัสดุเข้ากับงาน พร้อมคำนวณอัตราการใช้และแจ้งเตือนทันทีหาก "สต๊อกไม่พอ"
บันทึกสภาพอากาศ, ปริมาณน้ำ (สำหรับพ่นยา) หรือจำนวนต้น (สำหรับใส่ปุ๋ย)
ระบบตัดสต๊อกอัตโนมัติ: เมื่อเปลี่ยนสถานะงานเป็น "เสร็จสิ้น (Activated)" ระบบจะไปหักลบจำนวนพัสดุในสต๊อกให้ทันที
ระบบออกรายงาน PDF: สรุปประวัติการทำงาน (GAP Log) สามารถกรองดูเฉพาะ "ชื่อแปลง" หรือ "เดือน" ที่ต้องการ เพื่อปริ้นต์ส่งเจ้าหน้าที่ตรวจประเมิน GAP ได้เลย
ระบบรักษาความปลอดภัย: มีหน้า Login ป้องกันข้อมูลฟาร์มรั่วไหล

--------
จงสวมบทบาทเป็นนักพัฒนาเว็บไซต์ Full-Stack ผู้เชี่ยวชาญ ฉันต้องการให้คุณสร้างแอปพลิเคชันสำหรับจัดการฟาร์มและจดบันทึกมาตรฐาน GAP (Good Agricultural Practices) โดยให้ตั้งชื่อแอปว่า "Farm Planner"
**เทคโนโลยีที่ต้องใช้ (Tech Stack):**
- เฟรมเวิร์ก: Next.js (ใช้ App Router และ TypeScript)
- ตัวจัดการฐานข้อมูล (ORM): Prisma
- ฐานข้อมูล: PostgreSQL (หรือฐานข้อมูลเชิงสัมพันธ์อื่นๆ)
- ระบบยืนยันตัวตน: NextAuth.js (ใช้ Credentials Provider สำหรับผู้ดูแลระบบ)
- การตกแต่ง (Styling): Vanilla CSS Modules หรือ Tailwind CSS (เน้นความสะอาดตา ทันสมัย รองรับการใช้งานบนมือถือเป็นหลัก โทนสีหลักคือ ขาว ม่วง และแซมด้วยสีเขียว)
**โครงสร้างฐานข้อมูล (Database Schema):**
1. User: username, password, role
2. Inventory (พัสดุ): name, type (ปุ๋ย FERTILIZER, ยา CHEMICAL), quantity (ปริมาณฐาน), usageRate (อัตราการใช้), unit (หน่วยฐาน เช่น ก.ก., ซีซี), usageUnit (หน่วยที่ใช้แสดงผล เช่น กระสอบ, ขวด), conversionRate (อัตราการแปลงหน่วย เช่น 1 กระสอบ = 50 ก.ก.)
3. Task (งาน): title, date, icon, color, plot (แปลง), status (WAITING, ACTIVATED), waterVolume (ใช้เก็บข้อมูลปริมาณน้ำสำหรับพ่นยา หรือ จำนวนต้นสำหรับใส่ปุ๋ย), isWarningAcknowledged
4. TaskUsage: เป็นตัวเชื่อมระหว่าง Task และ Inventory เพื่อเก็บข้อมูลปริมาณพัสดุที่ใช้ในแต่ละงาน
**ฟีเจอร์และหน้าจอหลัก (Core Features & Pages):**
1. **ระบบล็อกอิน (Authentication):** 
   - มีหน้า Login ผู้ใช้ที่ล็อกอินแล้วเท่านั้นจึงจะเข้าถึงระบบจัดการได้
2. **หน้าจัดการสต๊อก (`/inventory`):**
   - แบ่งเป็น 2 ฝั่ง/ส่วน คือ "รายการปุ๋ย" และ "รายการยา/สารเคมี"
   - สามารถ เพิ่ม (Create), แก้ไข (Update) และ ลบ (Delete) พัสดุได้
   - แสดงยอดคงเหลือให้เข้าใจง่าย เช่น "เหลือ: 2 กระสอบ (100 ก.ก.)"
   - ต้องมีระบบ Checkbox สำหรับเลือกลบทีละหลายรายการ (Batch Delete)
3. **หน้าปฏิทินแผนงาน (`/planner`):**
   - แสดงปฏิทินรายเดือนและงานที่มีในแต่ละวัน
   - คลิกที่วันเพื่อสร้างงานใหม่ หรือคลิกที่งานเพื่อแก้ไข
   - **ระบบในหน้าต่างแก้ไขงาน (Task Modal):**
     - ข้อมูลที่ต้องกรอก: วันที่, ชื่องาน, แปลง (Plot), สถานะ, ไอคอน, สี
     - ถ้าชื่องานมีคำว่า "พ่น" ให้แสดงช่องกรอก "จำนวนถังที่ใช้ (200L/ถัง)" ถ้าชื่องานมีคำว่า "ใส่" ให้แสดงช่อง "จำนวนต้น:" โดยบันทึกค่านี้ลงในฟิลด์ `waterVolume`
     - สามารถเลือกพัสดุ (Inventory) หลายรายการเพื่อใช้ในงานนี้ได้
     - **ระบบแจ้งเตือน:** ถ้าระบุปริมาณพัสดุที่ต้องใช้ "มากกว่า" สต๊อกที่มีอยู่จริง ให้แสดงคำเตือน "⚠️ สต๊อกไม่พอ ขาดอีก..." ทันที
     - **ระบบหักสต๊อกอัตโนมัติ:** เมื่อเปลี่ยนสถานะงานเป็น "เสร็จสิ้น (ACTIVATED)" ให้ระบบไปหักลบจำนวนพัสดุในฐานข้อมูลสต๊อกทันที และถ้าเปลี่ยนสถานะกลับเป็น "รอดำเนินการ (WAITING)" ให้คืนยอดสต๊อกกลับมา
4. **ระบบออกรายงาน PDF:**
   - มีปุ่มสำหรับกดเพื่อดึงประวัติการทำงาน (GAP Log) ออกมาเป็นไฟล์ PDF (ใช้ไลบรารี html2canvas + jspdf หรือตัวอื่นๆ ที่เหมาะสม)
   - ต้องมีฟีเจอร์ "กรองตามแปลง (Filter by Plot)" เพื่อให้ผู้ใช้เลือกสร้างรายงาน PDF เฉพาะของแปลงที่ต้องการ ส่งให้เจ้าหน้าที่ประเมิน GAP ได้
5. **แนวทางการออกแบบและ UX (Design & UX):**
   - หน้าตาแอป (UI) ต้องยืดหยุ่น (Responsive) และแสดงผลบนหน้าจอมือถือได้ดีเยี่ยม (เพราะเกษตรกรต้องใช้หน้างาน)
   - ใช้ภาษาไทยทั้งหมดในส่วนติดต่อผู้ใช้งาน (UI)
   - ห้ามไม่ให้มีการแทรกข้อมูลจำลอง (Mock data seeding) ในขั้นตอนการ Build สำหรับระบบใช้งานจริง (Production)
โปรดให้โค้ดทีละขั้นตอน โดยเริ่มจากการสร้าง Prisma schema ตามด้วย API routes และสุดท้ายคือส่วนของ Frontend page และ component ต่างๆ
